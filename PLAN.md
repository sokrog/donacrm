# План Dona CRM

## Цель

Локальное Blazor-приложение для ведения Instagram-магазина одежды. Основное хранилище первой рабочей версии — Google Sheets; фотографии хранятся в Google Drive. Архитектура не должна связывать UI с конкретным хранилищем, чтобы позднее перейти на PostgreSQL.

> **Актуально:** синхронизация использует один версионированный JSON-снимок `dona-crm-sync-v1.json` в скрытой папке приложения (`appDataFolder`) личного Google Drive; личные ZIP-копии и новые фотографии товаров лежат там же. Google Sheets и ID таблицы/папки больше не используются. OAuth scopes: `openid email profile`, `drive.appdata`, `drive.file` (полный `drive` и `spreadsheets` не запрашиваются); нужен только Google Drive API. Windows читает Desktop OAuth Client ID и Secret из `appsettings.{Environment}.json` (`GoogleOAuth:WindowsClientId`, `GoogleOAuth:WindowsClientSecret`), они поставляются вместе с приложением — для установленных приложений Google не считает секрет конфиденциальным. После смены scopes пользователям нужно один раз войти заново.

Описание листов ниже — историческая модель данных первого адаптера и в текущей синхронизации не применяется.

## Модель данных Google Sheets (историческая)

Каждая сущность хранится на отдельном листе. Идентификаторы — GUID, даты — ISO 8601, денежные значения — числа без форматированного текста.

| Лист | Назначение | Ключевые колонки |
|---|---|---|
| Products | Карточки моделей | Id, Sku, Name, CategoryId, SupplierId, Status, PurchasePriceCny, PurchaseCurrencyCode, CostUzs, SellingPriceUzs |
| ProductVariants | Цвета, размеры, остатки | Id, ProductId, Color, Size, Quantity, ReservedQuantity |
| ProductImages | Галерея товара | Id, ProductId, FileName, Storage, StorageKey, Url, Caption, SortOrder, IsMain |
| Suppliers | Поставщики 1688/Taobao | Id, Name, StoreUrl, Rating, Mooq, Notes |
| Categories | Справочник категорий | Id, Name, SortOrder |
| Collections | Сезонные и маркетинговые подборки | Id, Name, Description, Status |
| CollectionProducts | Связь many-to-many | CollectionId, ProductId, SortOrder |
| Outfits | Готовые образы | Id, Name, Occasion, Status |
| OutfitProducts | Состав образа | OutfitId, ProductId, SellingPriceUzs, SortOrder |
| ContentPlan | План публикаций | Id, Title, Type, Status, ScheduledAt, CollectionId, OutfitId |
| AppSettings | Бизнес-правила | Key, Value |
| Sales | Заказы | Id, Number, CustomerName, Status, PaymentMethod, CreatedAt |
| SaleItems | Позиции заказа | Id, SaleId, ProductVariantId, Quantity, UnitPriceUzs, UnitCostUzs |
| SaleReturns | Документы возврата продажи | Id, SaleId, CreatedAt, Reason, RefundAmountUzs |
| SaleReturnItems | Позиции частичного возврата | ReturnId, SaleItemId, Quantity, Disposition |
| Payments | Оплаты и возвраты денег | Id, SaleId, Type, Status, Method, AmountUzs, CreatedAt |
| StockMovements | История изменения склада | Id, Type, ProductId, ProductVariantId, QuantityDelta, ReservedDelta, SourceId, CreatedAt |
| PurchaseReceipts | Документы частичной приёмки | Id, PurchaseId, ReceivedAt, Note |
| PurchaseReceiptItems | Фактические строки приёмки | ReceiptId, PurchaseItemId, ReceivedQuantity, DefectQuantity, StockedQuantity |
| Settings | Настройки расчётов | Key, Value |

## Этапы

### 1. Каталог — реализован первый срез

- каркас Blazor Server и адаптивный интерфейс;
- товар, варианты, статусы;
- расчёт закупочной экономики;
- дашборд, список, поиск, фильтр, создание и редактирование;
- локальное хранилище для запуска без Google Cloud.

### 2. Google Sheets и Drive — исторический адаптер каталога (заменён снимком в Drive appData)

- сервисный аккаунт и диагностика конфигурации Google Sheets;
- однократное подключение личного Google Drive через OAuth Desktop client с локальным refresh token;
- `GoogleSheetsCatalogRepository` через Sheets API v4;
- автоматическое создание/проверка заголовков листов;
- пакетное чтение и запись;
- импорт локального каталога в Google Sheets;
- переключение хранилища через конфигурацию;
- локальное хранение изображений и загрузка в выбранную папку Google Drive;
- галерея товара, главное фото, сортировка, подписи и удаление файлов;
- защищённая выдача непубличных файлов Drive через приложение;
- серверный и браузерный кэш Drive-изображений, ленивое отображение и индикатор загрузки — реализовано;
- optimistic concurrency и журнал операций — далее;
- резервный экспорт.

### 3. Справочники и закупки — первый рабочий срез реализован

- поставщики и редактируемые категории;
- отдельный справочник логистических посредников и их тарифов;
- закупки и позиции закупки;
- статусы движения из Китая;
- выбор исходной валюты товара и закупки, курс в главную валюту проекта, комиссия, доставка и прочие расходы — реализовано;
- распределение доставки по весу (с резервным распределением по количеству);
- приёмка: получено, брак, недостача и оприходованное количество;
- защита от повторного оприходования уже принятого количества;
- обновление фактической себестоимости товара при приёмке;
- история закупочных цен и курсов с раздельным учётом валют и фактической себестоимости в главной валюте по каждой приёмке — реализовано;
- отдельный экран `Цены и курсы` с фильтрами и сравнением поставщиков по средней себестоимости — реализовано;
- сравнение поставщиков по себестоимости, браку, полноте и срокам с рейтингом надёжности — реализовано;
- карточка поставщика с фактическими показателями, закупками и последними ценами — реализовано;
- сравнение закупочной цены одного товара у разных поставщиков — реализовано;
- связь закупки с конкретным посредником с хранением в локальном JSON и Google Sheets — реализовано;
- отчёт по посреднику: объём, вес, стоимость доставки за кг, фактический срок и задержки — реализовано;
- рейтинг посредника по фактическим срокам и ручной оценке — реализовано;
- далее: складская аналитика и резервное копирование;
- журнал складских движений для приёмки, резерва, продажи, отмены и возврата — реализован первый срез;
- ручные корректировки склада с причиной и контролем зарезервированного количества — реализовано;
- частичные поставки с отдельной историей приёмок и статусом закупки — реализовано;
- отдельные листы Google Sheets `ProductCostHistory` и `ExchangeRateHistory` с защитой от повторной записи одной приёмки — реализовано;

### 4. Продажи и склад — первый рабочий срез реализован

- клиенты, заказ и позиции заказа;
- резерв и автоматическое списание варианта;
- защита от повторного резерва, списания и возврата;
- способы оплаты и доставки, отмена и полный возврат;
- прибыль по зафиксированной фактической себестоимости;
- доступный остаток при выборе варианта;
- отдельные листы Google Sheets `Customers`, `Sales` и `SaleItems`;
- частичные возвраты отдельными документами с возвратом на склад, списанием брака или отказом — реализовано;
- чистая выручка и себестоимость учитывают частичные возвраты;
- частичные оплаты, несколько платежей, задолженность и фактические возвраты денег — реализовано;
- далее: частичные возвраты, журнал складских движений и статусы оплаты.

### 5. Instagram-контент и аналитика — первый срез контент-плана реализован

- коллекции с упорядоченным составом товаров;
- готовые образы с зафиксированными ценами и общей стоимостью;
- контент-план для фото, Reels, Stories, каруселей, обзоров и распаковок;
- связь публикаций с коллекциями и образами;
- статусы подготовки и фильтрация публикаций;
- отдельные нормализованные листы Google Sheets для контента;
- аналитика завершённых продаж за выбранный период;
- выручка, себестоимость, прибыль, маржа и средний чек;
- динамика по дням и рейтинги товаров, категорий и клиентов;
- далее: показатели маркетинговой воронки;
- отчёты по поставщикам, посредникам, коллекциям, образам и контенту — реализованы в расширенной аналитике.

### 6. Складская аналитика и режимы интерфейса — реализовано

- стоимость физического остатка, потенциальная выручка и прибыль;
- остаток, резерв и доступное количество по каждому варианту;
- продажи за 30/60/90 дней и прогноз запаса в днях;
- залежавшиеся позиции, сумма замороженных денег и рекомендации;
- аналитика стоимости склада по категориям;
- простой режим с базовой аналитикой, каталогом, продажами и маркетингом;
- расширенный режим со всеми операционными разделами;
- выбранный режим и порог залежавшегося товара сохраняются локально или в `AppSettings` Google Sheets.

### 7. Расширенная прибыль и эффективность маркетинга — реализовано

- прибыль по поставщикам и посредникам с атрибуцией по последней приёмке до продажи;
- прибыль по категориям, коллекциям и готовым образам;
- единый период фильтрации для всех финансовых срезов;
- эффективность опубликованного контента: товары, заказы, выручка и прибыль после публикации;
- выявление товаров из опубликованных подборок, которые не получили продаж;
- пояснение метода атрибуции непосредственно на экране аналитики.

### 8. Ускорение ежедневной работы — первый срез реализован

- резервная ZIP-копия данных активного хранилища и локальных изображений;
- дублирование товара с новым SKU, нулевыми остатками и без общих физических файлов;
- создание продажи из карточки товара с предварительно заполненной позицией;
- автоматический номер продажи с настраиваемым префиксом и защитой от дубликатов;
- новые действия встроены в существующие карточки и настройки без дополнительных пунктов меню.

## Дальнейший план

Главный принцип следующих итераций: не добавлять новые пункты меню, если действие можно безопасно встроить в существующую карточку, список, главную страницу или настройки. Расширенные возможности не должны мешать базовому сценарию `товар → продажа → остаток`.

### 9. Надёжное восстановление — реализован безопасный предпросмотр

- загрузка ZIP-копии на странице настроек — реализовано;
- проверка структуры, версии схемы и повреждённых файлов до любых изменений — реализовано;
- предпросмотр количества товаров, продаж, закупок, справочников и изображений — реализовано;
- отдельный показ новых и обновляемых товаров, закупок и продаж — реализовано; конфликты — далее;
- обязательное подтверждение перед восстановлением;
- восстановление локальных изображений без credentials и OAuth-токенов;
- автоматическая локальная копия перед каждым восстановлением;
- хранение последних семи автоматических копий с датой создания.

Критерий готовности: пользователь может проверить архив, увидеть последствия, отменить операцию без изменений или восстановить данные и получить отчёт о результате.

### 10. Качество данных без дополнительных форм

- проверка уникальности SKU при создании, копировании и редактировании товара;
- предупреждение о товаре без изображения, цены, категории или вариантов;
- предупреждение о продаже ниже себестоимости с явным подтверждением;
- защита от ухода со страницы с несохранёнными изменениями;
- быстрые фильтры `Без фото`, `Без цены`, `Без вариантов`, `Заканчивается` в существующем каталоге;
- сортировка товара по дате, цене, остатку, прибыли и наценке;
- кнопка сброса фильтров без повторной загрузки Google Sheets.

Критерий готовности: ошибки обнаруживаются до сохранения или продажи, а исправление выполняется в текущей карточке без отдельного раздела.

### 11. Меньше повторного ввода

- запоминание последнего способа оплаты и доставки;
- подстановка последнего курса юаня, поставщика и посредника при создании закупки;
- настройка значений по умолчанию в существующей секции бизнес-правил;
- сохранение последних фильтров и сортировки отдельно для каждого рабочего списка;
- быстрые действия `Продать`, `Создать закупку` и `Создать копию` только в контексте выбранного товара.

Критерий готовности: типовая продажа и типовая закупка требуют только выбора отличающихся значений.

### 12. Конфликты и целостность Google Sheets

- версия набора данных или метка последнего изменения;
- optimistic concurrency перед записью;
- отказ от молчаливого перезаписывания данных, изменённых в другом окне;
- понятный выбор: перечитать данные, сохранить копию или повторить после проверки;
- идентификаторы операций для защиты от повторной записи продажи, приёмки и возврата;
- резервная копия перед массовыми изменениями.

Критерий готовности: одновременная работа в двух окнах не приводит к незаметной потере более новых данных.

### 13. Ненавязчивый центр внимания на главной

- неоплаченные и частично оплаченные продажи;
- ожидаемые и просроченные поставки;
- низкий и нулевой доступный остаток;
- товары без фото, цены или вариантов;
- залежавшиеся позиции;
- переход из предупреждения сразу в существующую карточку.

Отдельный пункт меню не создаётся. На главной показываются только проблемы, требующие действия; если проблем нет, блок сворачивается.

### 14. Экспорт и переносимость

- Excel-экспорт каталога, остатков, продаж и закупок;
- выбор периода и состава экспорта;
- человекочитаемые названия и денежные форматы;
- сохранение идентификаторов в технических колонках для будущего обратного импорта;
- проверка совместимости ZIP-копии при изменении модели данных.

### 15. Импорт товаров из Китая — остаётся отложенным

- возобновить после появления стабильного доступа к 1688 и другим площадкам;
- начать с предпросмотра без автоматического сохранения;
- использовать существующие `ProductImages`, поставщиков, категории и механизм копирования изображений;
- добавить дедупликацию исходных ссылок и журнал импорта;
- не связывать базовую работу каталога с доступностью внешней площадки.

### Что пока сознательно не добавляем

- новые уровни меню и отдельные экраны для небольших действий;
- сложную ролевую модель для одного пользователя;
- несколько складов и адресное хранение без реальной потребности;
- полноценную бухгалтерию и налоговую отчётность внутри CRM;
- мобильное приложение до стабилизации основных сценариев веб-версии;
- автоматизации, которые меняют остатки или деньги без явного документа и подтверждения.

### Порядок реализации

1. Восстановление из резервной копии.
2. Уникальный SKU, контроль неполных данных и несохранённых изменений.
3. Быстрые фильтры, сортировка и запоминание значений.
4. Защита конфликтов Google Sheets.
5. Центр внимания на главной.
6. Excel-экспорт.
7. Импорт 1688 после восстановления доступа.

## Важные решения

- Google Sheets — только адаптер хранения; бизнес-правила остаются в приложении.
- Остаток ведётся на уровне варианта, а не модели товара.
- Себестоимость продажи фиксируется в `SaleItems`, поэтому будущая смена закупочной цены не искажает историю.
- Операции продажи и списания требуют защиты от частичной записи; до появления БД используется журнал операций и пакетное обновление Sheets.
- Статус складского товара рассчитывается централизованно по доступному остатку и настраиваемому порогу; архив и товары без вариантов не изменяются автоматически.
- Неактуальные товары архивируются без удаления истории и могут быть восстановлены с повторным расчётом складского статуса.
- Продажа проходит контролируемую цепочку статусов; резерв и физический остаток изменяются одной складской операцией, отрицательный остаток запрещён.
- Выбор товара в рабочих документах выполняется через единый autocomplete по SKU и названию; блокирующая загрузка показывается только при первом открытии, последующие операции используют неблокирующую полосу прогресса.
- Все рабочие списки используют локальную фильтрацию уже загруженных данных по поиску, статусу и параметрам конкретного раздела без дополнительных запросов к Google Sheets.
- Навигация сгруппирована по рабочим областям; складские изменения сохраняются отдельными неизменяемыми записями с привязкой к документу-источнику.
