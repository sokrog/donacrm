# План Dona CRM

## Цель

Локальное Blazor-приложение для ведения Instagram-магазина одежды. Основное хранилище первой рабочей версии — Google Sheets; фотографии хранятся в Google Drive. Архитектура не должна связывать UI с конкретным хранилищем, чтобы позднее перейти на PostgreSQL.

## Модель данных Google Sheets

Каждая сущность хранится на отдельном листе. Идентификаторы — GUID, даты — ISO 8601, денежные значения — числа без форматированного текста.

| Лист | Назначение | Ключевые колонки |
|---|---|---|
| Products | Карточки моделей | Id, Sku, Name, CategoryId, SupplierId, Status, PurchasePriceCny, CostUzs, SellingPriceUzs |
| ProductVariants | Цвета, размеры, остатки | Id, ProductId, Color, Size, Quantity, ReservedQuantity |
| Suppliers | Поставщики 1688/Taobao | Id, Name, StoreUrl, Rating, Mooq, Notes |
| Categories | Справочник категорий | Id, Name, SortOrder |
| Collections | Сезонные и маркетинговые подборки | Id, Name, Description, Status |
| CollectionProducts | Связь many-to-many | CollectionId, ProductId, SortOrder |
| Outfits | Готовые образы | Id, Name, Occasion, Status |
| OutfitProducts | Состав образа | OutfitId, ProductId, SellingPriceUzs, SortOrder |
| ContentPlan | План публикаций | Id, Title, Type, Status, ScheduledAt, CollectionId, OutfitId |
| AppSettings | Бизнес-правила | Key, Value |
| Sales | Заказы | Id, Number, CustomerName, Status, PaymentMethod, CreatedAt |
| SaleItems | Позиции заказа | Id, SaleId, ProductVariantId, Quantity, UnitPriceUzs, UnitCostUzs |
| SaleReturns | Документы возврата продажи | Id, SaleId, CreatedAt, Reason, RefundAmountUzs |
| SaleReturnItems | Позиции частичного возврата | ReturnId, SaleItemId, Quantity, Disposition |
| Payments | Оплаты и возвраты денег | Id, SaleId, Type, Status, Method, AmountUzs, CreatedAt |
| StockMovements | История изменения склада | Id, Type, ProductId, ProductVariantId, QuantityDelta, ReservedDelta, SourceId, CreatedAt |
| PurchaseReceipts | Документы частичной приёмки | Id, PurchaseId, ReceivedAt, Note |
| PurchaseReceiptItems | Фактические строки приёмки | ReceiptId, PurchaseItemId, ReceivedQuantity, DefectQuantity, StockedQuantity |
| Settings | Настройки расчётов | Key, Value |

## Этапы

### 1. Каталог — реализован первый срез

- каркас Blazor Server и адаптивный интерфейс;
- товар, варианты, статусы;
- расчёт закупочной экономики;
- дашборд, список, поиск, фильтр, создание и редактирование;
- локальное хранилище для запуска без Google Cloud.

### 2. Google Sheets и Drive — адаптер каталога реализован

- сервисный аккаунт и диагностика конфигурации;
- `GoogleSheetsCatalogRepository` через Sheets API v4;
- автоматическое создание/проверка заголовков листов;
- пакетное чтение и запись;
- импорт локального каталога в Google Sheets;
- переключение хранилища через конфигурацию;
- optimistic concurrency и журнал операций — далее;
- загрузка фотографий в заданную папку Drive;
- резервный экспорт.

### 3. Справочники и закупки — первый рабочий срез реализован

- поставщики и редактируемые категории;
- отдельный справочник логистических посредников и их тарифов;
- закупки и позиции закупки;
- статусы движения из Китая;
- курс валюты, комиссия, доставка и прочие расходы;
- распределение доставки по весу (с резервным распределением по количеству);
- приёмка: получено, брак, недостача и оприходованное количество;
- защита от повторного оприходования уже принятого количества;
- обновление фактической себестоимости товара при приёмке;
- история закупочных цен, курса CNY и фактической себестоимости по каждой приёмке — реализовано;
- отдельный экран `Цены и курсы` с фильтрами и сравнением поставщиков по средней себестоимости — реализовано;
- далее: расширенное сравнение поставщиков по браку, срокам и полноте поставок;
- журнал складских движений для приёмки, резерва, продажи, отмены и возврата — реализован первый срез;
- ручные корректировки склада с причиной и контролем зарезервированного количества — реализовано;
- частичные поставки с отдельной историей приёмок и статусом закупки — реализовано;
- отдельные листы Google Sheets `ProductCostHistory` и `ExchangeRateHistory` с защитой от повторной записи одной приёмки — реализовано;

### 4. Продажи и склад — первый рабочий срез реализован

- клиенты, заказ и позиции заказа;
- резерв и автоматическое списание варианта;
- защита от повторного резерва, списания и возврата;
- способы оплаты и доставки, отмена и полный возврат;
- прибыль по зафиксированной фактической себестоимости;
- доступный остаток при выборе варианта;
- отдельные листы Google Sheets `Customers`, `Sales` и `SaleItems`;
- частичные возвраты отдельными документами с возвратом на склад, списанием брака или отказом — реализовано;
- чистая выручка и себестоимость учитывают частичные возвраты;
- частичные оплаты, несколько платежей, задолженность и фактические возвраты денег — реализовано;
- далее: частичные возвраты, журнал складских движений и статусы оплаты.

### 5. Instagram-контент и аналитика — первый срез контент-плана реализован

- коллекции с упорядоченным составом товаров;
- готовые образы с зафиксированными ценами и общей стоимостью;
- контент-план для фото, Reels, Stories, каруселей, обзоров и распаковок;
- связь публикаций с коллекциями и образами;
- статусы подготовки и фильтрация публикаций;
- отдельные нормализованные листы Google Sheets для контента;
- аналитика завершённых продаж за выбранный период;
- выручка, себестоимость, прибыль, маржа и средний чек;
- динамика по дням и рейтинги товаров, категорий и клиентов;
- далее: показатели маркетинговой воронки;
- далее: отчёты по поставщику и коллекции.

## Важные решения

- Google Sheets — только адаптер хранения; бизнес-правила остаются в приложении.
- Остаток ведётся на уровне варианта, а не модели товара.
- Себестоимость продажи фиксируется в `SaleItems`, поэтому будущая смена закупочной цены не искажает историю.
- Операции продажи и списания требуют защиты от частичной записи; до появления БД используется журнал операций и пакетное обновление Sheets.
- Статус складского товара рассчитывается централизованно по доступному остатку и настраиваемому порогу; архив и товары без вариантов не изменяются автоматически.
- Неактуальные товары архивируются без удаления истории и могут быть восстановлены с повторным расчётом складского статуса.
- Продажа проходит контролируемую цепочку статусов; резерв и физический остаток изменяются одной складской операцией, отрицательный остаток запрещён.
- Выбор товара в рабочих документах выполняется через единый autocomplete по SKU и названию; блокирующая загрузка показывается только при первом открытии, последующие операции используют неблокирующую полосу прогресса.
- Все рабочие списки используют локальную фильтрацию уже загруженных данных по поиску, статусу и параметрам конкретного раздела без дополнительных запросов к Google Sheets.
- Навигация сгруппирована по рабочим областям; складские изменения сохраняются отдельными неизменяемыми записями с привязкой к документу-источнику.
