# Аудит структуры брендбука

## Найденные проблемы
- Порядок навигации не совпадал с содержимым: названия находились после макетов.
- Выбор логотипа отделяла от настроек длинная секция упаковки.
- Настройки бренда смешивались с темой цифровых носителей.
- Редактор прерывал просмотр примеров, а загрузки были распределены без общего раздела.
- Повторные сравнения символов и пояснения занимали столько же внимания, сколько основной выбор.
- Выбор настроения незаметно заменял уже выбранное имя.

## Новая структура
1. Бренд: имя → настроение → настройки и предпросмотр → выбор логотипа. Смысл имён и сравнение символов раскрываются по запросу.
2. Носители: упаковка и одежда → вывеска → тема цифровых макетов → соцсети → приложение. Локальная навигация ведёт к каждому виду.
3. Редактор: позиционирование и экспорт макета; фиксированные эскизы сохраняют блокировку настроек.
4. Файлы и правила: скачивание текущего варианта, общего архива, иконок, исходников; исходные доски и рекомендации.

Экраны имеют отдельные адреса через hash, поддерживают Back/Forward и старые якоря. Общее состояние бренда сохраняется между экранами и отражается в закреплённой строке. Это не отдельные независимые HTML-файлы: единый документ сохраняет автономный экспорт и совместимость с GitHub Pages.

## Проверка
Проверены переключение всех четырёх экранов, сохранение выбранного имени после смены настроения, блокировка редактора для ImageGen, отсутствие дублирующихся ID, встраивание ресурсов в автономный HTML и сборка GitHub Pages.
