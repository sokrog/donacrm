# Dona — интерактивный брендбук

Интерактивная клиентская презентация для магазина женской одежды, аудитория 24–38 лет. Версия 08: Ruby + Rose Ivory, четыре имени, пять новых знаков ImageGen, 60 редактируемых композиций, реалистичные носители и скачивание материалов.

## Просмотр

Готовый `dona-brandbook.html` можно открыть двойным щелчком и переслать как один файл: он работает офлайн, включая экспорт. Чтобы обновить этот файл после изменения исходников, выполните `python design/dona-brandbook/build.py` из корня репозитория.

Из корня репозитория:

```powershell
python -m http.server 5189 --bind 127.0.0.1 --directory design/dona-brandbook
```

Откройте http://127.0.0.1:5189. Модульный `index.html` открывайте через сервер: он загружает локальные изображения и лицензии. Для двойного щелчка без сервера используйте `dona-brandbook.html`.

## Публикация на GitHub Pages

Страница подготовлена для публикации из этого репозитория через GitHub Actions. Node.js, .NET, база данных и установка Python-пакетов для сборки не нужны.

```text
.github/workflows/brandbook-pages.yml   — автоматическая сборка и публикация
design/dona-brandbook/
  index.html                          — главная страница сайта
  app.js                              — интерактивность и экспорт
  assets.js / assets/                  — загрузчик и PNG-материалы ImageGen
  client.css                          — клиентская версия оформления
  *.css                               — оформление, встроенные шрифты и фото
  licenses/                           — лицензии шрифтов
  build.py                            — сборка сайта или офлайн-файла
  dist/                               — готовый сайт, исключён из Git
  dona-brandbook.html                 — отдельная офлайн-версия
```

### Первый запуск

1. Сохраните в Git исходники `design/dona-brandbook/` и workflow `.github/workflows/brandbook-pages.yml`, затем отправьте их в ветку `main` на GitHub. Текущие изменения из рабочей ветки сначала нужно перенести в `main`.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Во вкладке **Actions** выберите **Publish Dona brandbook → Run workflow → main → Run workflow**. Это также позволяет повторить публикацию, если первая попытка произошла до включения Pages.
4. После успешного задания `deploy` откройте URL в его окружении `github-pages`. Для текущего репозитория ожидаемый адрес: **https://sokrog.github.io/donacrm/** (если не настроен собственный домен).

Последующие изменения папки брендбука в `main` публикуются автоматически. Запуск из других веток пропускается. Для другого репозитория скопируйте папку брендбука с тем же путём и workflow; если основная ветка называется иначе, замените `main` в `branches` и `if` workflow.

Настройка следует [официальной инструкции GitHub Pages для custom workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). Для приватного репозитория доступность Pages зависит от тарифа GitHub.

### Локальная проверка сборки

Из корня репозитория:

```powershell
python design/dona-brandbook/build.py --pages
python -m http.server 5190 --bind 127.0.0.1 --directory design/dona-brandbook/dist
```

Откройте http://127.0.0.1:5190/. В `dist/` копируются только HTML, два JS-файла, пять CSS-файлов, PNG из `assets/`, лицензии и `.nojekyll`. Все пути относительные, поэтому сайт работает и в корне домена, и по адресу `/donacrm/`. Шрифты встроены в CSS, фотографии и знаки хранятся в `assets/`. Для автономных SVG/PNG загрузчик переводит изображения в data URI. Экспорт HTML загружает исходники с того же сайта; PNG и SVG формируются в браузере.

`dist/` не нужно коммитить: Actions создаёт её самостоятельно. Если в ней оказались посторонние файлы, сборка остановится и перечислит их, чтобы они не попали в публикацию. Обычный запуск `python design/dona-brandbook/build.py` по-прежнему обновляет только самодостаточный `dona-brandbook.html` для пересылки офлайн.

Публикуется исходный набор концептов. Выбранные в редакторе настройки остаются в браузере конкретного посетителя; перенос выбранного варианта предусмотрен кнопкой «Сохранить брендбук».

## Клиентская версия 08

- Названия: **DONA, Dona Muse, Dona Belle, Belle Dona** и ручное название до 32 символов.
- Символы: шёлковый бант, вишня, реалистичный отпечаток помады, тюльпан и лебедь. Только заливочное исполнение. Старые символы и контурный режим убраны.
- Три композиции для каждой пары имени и символа: редакционная антиква, личная подпись, дом бренда. Для двойных имён — рукописное второе слово и набор в две строки; для тюльпана — боковая ботаническая композиция. Всего 4 × 5 × 3 = **60** сочетаний. Для ручного названия доступны три общих композиции.
- Четыре палитры, каждая с летней и зимней версией: Ruby / Rose Ivory, Cherry / Cream, Burgundy / Petal, Rosewood / Milk. Исходные клиентские цвета: `#66021F` и `#FFE9EC`; соседняя пара — `#630625` и `#F5B7BD`.
- Пять встроенных семейств: Prata, Cormorant Garamond, Manrope, Marck Script, Great Vibes, плюс системные альтернативы. Great Vibes используется для латинской подписи; кириллицу поддерживает Marck Script.
- Фотоносители: пакет, коробка, благодарственная карточка, бирка, этикетка в горловине и небольшое нанесение на лонгслив. Логотип меняется вместе с выбором пользователя.
- Дневной и вечерний вид одного бутика: ночная фотография создана редактированием дневного кадра с сохранением архитектуры. На вывеске показан выбранный логотип; ночью — мягкое свечение.
- Светлая и тёмная темы приложения рядом, Instagram-профиль, тематические highlights, Telegram-публикация и Stories. Числа подписчиков — демонстрационные.
- Четыре отдельные доски ImageGen, по три эскиза для каждого имени. Их можно раскрыть и скачать. Это направления художественной разработки; интерактивные 60 композиций собраны из пяти созданных знаков и живой типографики.

## Редактор позиционирования

Сохранены девять готовых позиций, перетаскивание, стрелки клавиатуры (Shift — крупный шаг), X/Y, угол, размер, прозрачный фон и включение названия. Форматы: 1080×1350, 1080×1920, 1600×1000, 1080×1080. Кнопка «Применить ко всему брендбуку» переносит композицию на носители. В самостоятельных аватарах применяется только поворот; знак центрируется и вписывается в область.

## Скачивание

Раздел «Материалы бренда»:

- выбранная композиция PNG 1800×612 и SVG;
- ZIP со всеми 60 композициями SVG, текущим вариантом (в том числе ручным), пятью прозрачными исходниками символов, восемью тематическими иконками в SVG и PNG 1080×1080, палитрами, настройками и лицензиями;
- отдельные PNG исходников символов;
- иконки: новинки, образы, доставка, отзывы, примерка, уход, подарки, бутик;
- PNG каждого фотоносителя и вывески 1536×1024;
- доски эскизов ImageGen в исходном разрешении;
- самодостаточный HTML с текущим выбором через «Сохранить брендбук».

SVG композиций содержит **растровый знак ImageGen** и редактируемую типографику со встроенными шрифтами. Это не полностью векторный производственный оригинал. Иконки соцсетей построены в SVG. Для печати необходимы утверждение конкретного варианта, подготовка оригинала и проба на выбранном материале. Не заменяйте прозрачный PNG на JPEG, если нужен прозрачный фон.

Фактура знаков сохраняется через маску плотности пигмента; оттенок меняется вместе с палитрой. Исходные PNG доступны отдельно без преобразования. Фотографии имеют фиксированную рубиновую гамму, а нанесённые логотипы меняют цвет. ZIP может занимать около 100 МБ, поскольку каждый логотип автономен и содержит свой знак и шрифты.

## Источники и генерация

Генерация выполнена встроенным **imagegen**, без API CLI. Материалы находятся в `assets/`, промпты — в [generation-prompts.md](generation-prompts.md). Клиентские скриншоты использованы как визуальные ориентиры по цвету, типографике и характеру отпечатка; исходный логотип KAY’S не копировался.

Из [статьи-гида](https://dtf.ru/id3190783/4715568-sozdanie-logotipa-s-chatgpt) применён подход «бриф → варианты → отбор → носители → комплект файлов», с акцентом на читаемость имени, один доминирующий символ и проверку масштаба. Фотографии созданы для демонстрации айдентики, а не изображают реальные товары или существующий магазин.

## Проверка

Проверены все 20 пар имён/символов (три композиции каждая), ручное кириллическое имя, четыре зимние палитры, независимая тема, применение позиции. PNG этикетки проверен визуально и по размеру 1536×1024. ZIP сформирован в браузере; упаковщик отдельно проверен на CRC, распаковку, UTF-8 и бинарные данные. На узком экране 511 px горизонтального переполнения не обнаружено. Версии для Pages и автономного просмотра собираются без внешних пакетов.

### Фиксированные эскизы и иконки

В выборе логотипа доступны ещё 12 эскизов ImageGen (по три для каждого имени). Они используют исходные доски через SVG-маску, сохраняют авторскую типографику и взаимное размещение. Для них отключены шрифт, смена символа и калькулятор размещения. При ручном названии остаются три редактируемые конструкции. Фиксированные варианты входят в экспорт SVG/PNG и ZIP.

Тематические SVG-иллюстрации имеют отдельные силуэты и внутренние детали без сквозных пересечений. На тёмной поверхности используется светлая краска; в ZIP и индивидуальных загрузках доступны светлые PNG для тёмного фона.

Добавлены восемь фиксированных эскизов ImageGen с вишней и лебедем: по два для каждого имени. Всего 20 фиксированных эскизов и 60 редактируемых композиций; ZIP содержит все 80 вариантов. Исходные новые доски сохранены в assets/direction-*-cherry-swan.png.

### Индивидуальные комплекты эскизов

Каждая карточка ImageGen имеет собственные PNG (4000 px по длинной стороне, пропорции сохранены), SVG и ZIP. Скачивание не меняет выбранный логотип. ZIP содержит по PNG/SVG в цвете бренда, светлом оттенке палитры, чёрном и белом, а также README с разрешением исходного участка рисунка и ограничениями применения. Увеличение PNG не добавляет деталей; SVG сохраняет растровый оригинал через маску.


### Web previews and originals

The Pages build uses committed `previews/*.webp` (about 1.1 MB in total). Carrier images are rendered when the Applications screen opens. Full-size `assets/*.png` are fetched on demand for export, cached for the session, and embedded into SVG/PNG/offline HTML. Original downloads are limited to three concurrent requests and can be retried after errors. Each image URL uses its own content hash, so a code-only deployment preserves image caching.

After updating PNG artwork, regenerate previews with `python prepare_previews.py` (requires Pillow), and commit both versions. CI runs `node test-assets.cjs` to check lazy loading, deduplication, concurrency, and retries.
