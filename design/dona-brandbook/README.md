# Dona — интерактивный брендбук

Самостоятельная страница для обсуждения айдентики магазина женской одежды, аудитория 24–38 лет. Не изменяет рабочую CRM. Версия 07: редактор макетов с PNG-экспортом, контурное и заполненное исполнение, каллиграфическая D с росчерком, ботанический тюльпан, лебедь с длинной шеей, переработанные рисунки всех знаков, композиции с учётом совместимости, семь настроений и предметная фотография для клиентской презентации.

## Просмотр

Готовый `dona-brandbook.html` можно открыть двойным щелчком и переслать как один файл: он работает офлайн, включая экспорт. Чтобы обновить этот файл после изменения исходников, выполните `python design/dona-brandbook/build.py` из корня репозитория.

Из корня репозитория:

```powershell
python -m http.server 5189 --bind 127.0.0.1 --directory design/dona-brandbook
```

Откройте http://127.0.0.1:5189. Можно открыть `index.html` напрямую, но экспорт полного HTML в этом режиме зависит от ограничений браузера; используйте сервер для первоначального экспорта.

## Публикация на GitHub Pages

Страница подготовлена для публикации из этого репозитория через GitHub Actions. Node.js, .NET, база данных и установка Python-пакетов для сборки не нужны.

```text
.github/workflows/brandbook-pages.yml   — автоматическая сборка и публикация
design/dona-brandbook/
  index.html                          — главная страница сайта
  app.js                              — интерактивность и экспорт
  *.css                               — оформление, встроенные шрифты и фото
  licenses/                           — лицензии шрифтов
  build.py                            — сборка сайта или офлайн-файла
  dist/                               — готовый сайт, исключён из Git
  dona-brandbook.html                 — отдельная офлайн-версия
```

### Первый запуск

1. Сохраните в Git исходники `design/dona-brandbook/` и workflow `.github/workflows/brandbook-pages.yml`, затем отправьте их в ветку `main` на GitHub. Текущие изменения из рабочей ветки сначала нужно перенести в `main`.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Во вкладке **Actions** выберите **Publish Dona brandbook → Run workflow → main → Run workflow**. Это также позволяет повторить публикацию, если первая попытка произошла до включения Pages.
4. После успешного задания `deploy` откройте URL в его окружении `github-pages`. Для текущего репозитория ожидаемый адрес: **https://sokrog.github.io/donacrm/** (если не настроен собственный домен).

Последующие изменения папки брендбука в `main` публикуются автоматически. Запуск из других веток пропускается. Для другого репозитория скопируйте папку брендбука с тем же путём и workflow; если основная ветка называется иначе, замените `main` в `branches` и `if` workflow.

Настройка следует [официальной инструкции GitHub Pages для custom workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). Для приватного репозитория доступность Pages зависит от тарифа GitHub.

### Локальная проверка сборки

Из корня репозитория:

```powershell
python design/dona-brandbook/build.py --pages
python -m http.server 5190 --bind 127.0.0.1 --directory design/dona-brandbook/dist
```

Откройте http://127.0.0.1:5190/. В `dist/` копируются только `index.html`, `app.js`, четыре CSS-файла, лицензии и `.nojekyll`. Все пути относительные, поэтому сайт работает и в корне домена, и по адресу `/donacrm/`. Шрифты и фотография уже встроены в CSS. Экспорт HTML загружает исходники с того же сайта; PNG и SVG формируются в браузере.

`dist/` не нужно коммитить: Actions создаёт её самостоятельно. Если в ней оказались посторонние файлы, сборка остановится и перечислит их, чтобы они не попали в публикацию. Обычный запуск `python design/dona-brandbook/build.py` по-прежнему обновляет только самодостаточный `dona-brandbook.html` для пересылки офлайн.

Публикуется исходный набор концептов. Выбранные в редакторе настройки остаются в браузере конкретного посетителя; перенос выбранного варианта предусмотрен кнопкой «Сохранить брендбук».

## Редактор макета

Раздел «Разместите знак по-своему» поддерживает девять позиций, перетаскивание мышью/касанием, стрелки клавиатуры (Shift — шаг 5%), ползунки X/Y, угла −180…180° и размера 8…70%. Знак удерживается внутри холста с учётом поворота. Выбор символа и исполнения синхронизируется с брендбуком.

Форматы PNG: публикация 1080×1350, Stories 1080×1920, карточка 1600×1000, аватар 1080×1080. Можно отключить название и выбрать прозрачный фон. На всех носителях используется только полный рисунок. Контур и заливка строятся из общей геометрии, без отдельных упрощённых вариантов. Экспорт использует векторный знак и загруженный шрифт, без рамки редактора. Предыдущий PNG остаётся доступен до следующего экспорта; настройки сохраняются в браузере и в экспортированном HTML.

Кнопка «Применить ко всему брендбуку» сохраняет X/Y, угол и размер для логотипов, упаковки, аватаров, Stories и других макетов. Для отдельных знаков (аватары, highlights, поле символа в Stories) применяется только угол: знак центрируется и вписывается в область с полями. В логотипах с названием сохраняется единый масштаб и взаимное расположение знака и текста, включая пакет, бирку и публикацию. Формат исходного макета сохраняется вместе с композицией. Последующие правки редактора требуют повторного применения. «Вернуть исходные композиции» отменяет общее размещение; выбор готовой конструкции логотипа также возвращает исходную компоновку. Применённые настройки сохраняются в браузере, HTML и SVG-экспорте.

## Возможности

- 12 вариантов имени на базе Durdona / Dona с пояснениями.
- 7 направлений: Жемчужное ателье, Вишнёвое свидание, Тихая муза, Сад камелий, Балетная линия, Утро у моря, Личная подпись.
- 9 SVG-знаков. Четыре лепестка удалены; весь набор перерисован, добавлена интерактивная таблица сравнения. Орбита и нить удалены. Для аватаров используется тот же полный рисунок. Монограмма заменена читаемым инициалом D.
- 8 шрифтов: четыре прежних системных и встроенные Cormorant Garamond, Prata, Manrope, Marck Script с кириллицей. Google Fonts и лицензии OFL включены локально.
- Своё название до 32 символов, включая кириллицу; безопасное экранирование HTML/SVG и сохранение в браузере.
- 9 типов композиции, из которых для каждого знака показываются 3–5 подходящих: знак над именем, горизонтальная подпись, ботаническая виньетка, камея, лента, печать, инициал, открытка, подвеска. Автоматическая замена O/О удалена. Рисованная D может открывать только название, начинающееся с латинской D, в сочетании с антиквой. Смена символа или имени автоматически заменяет несовместимую композицию.
- По 2 летних и 2 зимних палитры на концепт; индивидуальный акцент для каждого сезона и направления.
- Светлая и тёмная темы макетов соцсетей, независимые от сезона.
- Instagram-профиль, highlights, сетка обложек 3:4, Stories 9:16 и Telegram-канал с карточкой публикации.
- Живое обновление логотипа, пакета, бирки, карточки коллекции, палитры и социальных носителей.
- Сохранение настроек в localStorage; сброс к исходному выбранному направлению.
- Экспорт самодостаточного интерактивного HTML с выбранными настройками, SVG выбранной композиции со встроенным веб-шрифтом и отдельного аватара SVG.
- Адаптивная вёрстка, клавиатурное управление, reduced motion и стили печати.

При просмотре внешних запросов нет. Шрифты включены как data URI, лицензии — в `licenses/` и CSS. `fetch-fonts.py` нужен только для обновления файлов с Google Fonts. `editorial-v3.png` — фотографическая иллюстрация, созданная ImageGen для презентации, не съёмка реального товара. Она встроена в `media.css` для офлайн-просмотра и повторно используется с разным кадрированием. Соцсети — макеты без подключения к аккаунтам. Перед публикацией нужна съёмка реальной коллекции. Экспорт SVG сохраняет редактируемый текст; поддержка встроенных шрифтов зависит от графического редактора, для печати требуется перевод в кривые.

## Статус дизайна

Это концепции, а не утверждённая производственная айдентика. Имена не проверены по товарным знакам, доменам и социальным сетям. В SVG текст сохраняется редактируемым: для печати нужны выбранный шрифт, перевод в кривые и проверка толщины линий. При произвольном акценте контраст текста на кнопке подбирается автоматически; контраст логотипа с фирменным фоном необходимо оценивать при выборе цвета.
