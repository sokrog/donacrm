# План: упрощение карточки товара и единые размеры контролов

## Принцип

Карточка товара содержит только то, что нужно, чтобы **завести товар и продать его**. Пользователь не бухгалтер, это не 1С. Себестоимость, партии, оборачиваемость, история закупок, маржа — в отчётах и на складе, не в карточке.

Продукт ещё не в работе, реальных данных нет. Обратная совместимость не нужна: лишние поля модели, хранилищ, синхронизации и бэкапа удалять полностью, без алиасов и миграций старого формата.

## Этап 0. Единая высота полей и кнопок (глобально)

**Все однострочные поля ввода, поля выбора и кнопки одной высоты. Поля подгоняются под высоту кнопок — 48px.**

Сейчас в [components.css](src/Dona.Crm.UI/wwwroot/styles/components.css) и компонентах высоты разные:

| Элемент | Сейчас |
|---|---|
| `.dona-field input/select`, `.dona-input`, `.dona-search input` | `--dona-control-height: 52px` |
| `OrbitSelect` (триггер) | 52px, внутри `min-height: 54px` |
| `OrbitDatePicker` | 46px |
| `.dona-btn` | `min-height: 48px` |
| `.dona-btn--icon`, `.dona-back-button`, `.dona-btn--remove` | 48px |
| `.dona-add-button` | 52px |
| `.dona-section-title > button/a` («+ Добавить» в секциях) | 44px |
| `.dona-toggle` | 44px + рамка |

Сделать:

1. В [tokens.css](src/Dona.Crm.UI/wwwroot/styles/tokens.css): `--dona-control-height: 48px`; `--dona-remove-size` и остальные размеры контролов ссылаются на него.
2. `.dona-btn` и все её варианты: `height` = `var(--dona-control-height)`, `box-sizing: border-box`.
3. Поля, селекты, `OrbitSelect`, `OrbitDatePicker`, `ProductAutocomplete`, поиск: та же высота. Убрать внутренние `min-height: 54px` / `46px`.
4. Кнопки в шапках секций, иконочные, «назад», «добавить», удаление строки — та же высота; квадратные — `width = height`.
5. `textarea` исключить из фиксированной высоты: сейчас общее правило даёт ей 52px, поэтому «Описание» в одну строку при `rows="5"`. Для неё `height: auto`, `rows` работает.
6. Текст в полях и кнопках по центру по вертикали, размер шрифта одинаковый.
7. Проверить ряды «поле + кнопка» на всех экранах (фото по ссылке, добавление категории, варианты товара, позиции закупки и продажи, поиск, фильтры): нижние края совпадают.

## Этап 1. Что убрать

1. **Себестоимость из карточки** — поля «Плановая цена», «Валюта плановой закупки», «Курс», «Плановая доставка», а также из модели `Product`: `PlannedPurchasePrice`, `PurchaseCurrencyCode`, `RateToUzs`, `AgentCommissionPercent`, `DeliveryCostUzs`, `CostPurchaseId`, `CostUzs`, `ProfitUzs`, `MarkupPercent`, алиасы `PurchasePriceCny`, `CnyRateUzs`. Убрать их из хранилищ (SQLite, браузер), синхронизации, бэкапа, приёмки закупки ([PurchaseReceivingService.cs:290](src/Dona.Crm.Core/Services/PurchaseReceivingService.cs:290)) и аналитики ([InventoryAnalyticsService.cs:28](src/Dona.Crm.Core/Services/InventoryAnalyticsService.cs:28)). Себестоимость берётся только из партий.
2. **«Начальный остаток» в вариантах.** Новый товар создаётся с нулевым остатком, без партий и движений ([ProductEditingService.cs](src/Dona.Crm.Core/Services/ProductEditingService.cs), ~стр. 94–106). Остаток появляется через приёмку закупки или корректировку остатка с причиной «Начальный остаток», где себестоимость вводится явно.
3. **Флажок «Можно заказать при отсутствии»** — убрать из модели, формы и списка товаров (значок в [Products.razor:101](src/Dona.Crm.UI/Pages/Products.razor:101)). На логику продаж он не влияет.
4. **«Заметка о магазине»** (`SupplierName` в товаре) — убрать.
5. **Строки-сводки с нулями** («Ожидается по открытым закупкам…», «Наличие: … Статус рассчитывается автоматически…») — убрать.
6. **Блок «Остаток по партиям»** — убрать из карточки. Партии без себестоимости показывать там, где работают со складом (склад / «Требует внимания»), со ссылкой «Указать стоимость».
7. **Ручной статус наличия** (`ManualStatusOptions`, настройка `AutoUpdateStockStatus`) — убрать, если используется только здесь: наличие всегда считается по остатку.

Подстановка цены в закупку ([PurchaseEditor.razor](src/Dona.Crm.UI/Pages/PurchaseEditor.razor), `ProductChanged`): брать цену из последней закупки этого товара в той же валюте; если такой нет — поле пустое.

## Этап 2. Что остаётся в карточке

Один экран, без отдельного режима просмотра.

**Основное**
- Название *
- SKU * — предлагать автоматически, можно изменить
- Категория, пол, сезон
- **Цена продажи, UZS** — просмотр, дата последнего изменения, переходы «Установить цену» и «История цен». Ввод цены перенесён в отдельную операцию по SELLING-PRICE-PLAN.md; новый товар сначала сохраняется.
- Описание — для клиента (материал, состав, посадка), многострочное

**Варианты** — цвет, размер; для сохранённого товара рядом с каждым вариантом «Доступно N» (на складе минус резерв). Одной строкой над списком: «Доступно всего N». Если товар едет в закупке — «Ожидается N» по варианту. Больше никаких цифр.
- Хотя бы один вариант обязателен.
- Одинаковые цвет и размер — ошибка, сохранение блокируется (сейчас только предупреждение).
- Причина, почему вариант нельзя удалить, видна текстом, не только в `title`.

**Фото**

**Закупка** — свёрнуто по умолчанию:
- Поставщик (подставляется в новую закупку)
- Ссылка на товар у поставщика
- Вес единицы, кг — новое поле, подставляется в позицию закупки; после приёмки заполняется, если пусто

**Действия**
- После создания товара — открыть его же карточку и показать: «Остатка пока нет. [Создать закупку] · [Внести остаток]».
- «В архив» / «Вернуть из архива» — внизу, второстепенно, с подтверждением.
- Новая категория попадает в справочник только при сохранении товара.

## Этап 3. Визуал формы

1. Подписи полей заметнее пояснений; пояснения — максимум одна короткая строка, большинство убрать.
2. Две колонки примерно равной высоты; на телефоне — одна, в порядке: основное → варианты → фото → закупка.
3. Обязательные поля отмечены.
4. Суммы UZS при просмотре с разделителями тысяч («2 500 000») и обозначением «UZS»; ввод цены в отдельной операции через общий числовой компонент.
5. Все кнопки добавления на экране одного стиля: «Добавить» у категории, вариантов, фото по ссылке и «Выбрать» у фото.
6. «Сохранить» — основная, справа; «Отмена» — компактная второстепенная, слева, не на полэкрана.
7. Удаление варианта — иконка, а не символ «×». У единственного варианта кнопка удаления неактивна.
8. Маркер раскрытия блока «Закупка» — иконка `OrbitIcon`, не системный треугольник.

Проверить на ширине 375px и ≥1280px, в светлой и тёмной теме.
