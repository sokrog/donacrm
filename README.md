# Dona CRM

Command Orbit использует единый интерфейс из `Dona.Crm.UI`: `Dona.Crm.App` запускает его как MAUI Blazor Hybrid на Android, iOS и Windows, а `Dona.Crm.Web.Client` — как браузерное WebAssembly/PWA-приложение. Старый серверный Web-host удалён после переноса бизнес-логики, синхронизации, Google Drive и регрессионных тестов.

## Command Orbit в браузере

```powershell
dotnet run --project src/Dona.Crm.Web.Client
```

Браузерная версия работает без серверного брокера: локальный снимок хранится в browser storage, интерфейс доступен как PWA, а Google OAuth использует Web Client ID напрямую. Ручная синхронизация пишет версионированный снимок `dona-crm-sync-v1.json` в скрытую папку приложения (`appDataFolder`) вашего Google Drive и проверяет версию перед заменой данных.

Локальная мини-CRM для магазина одежды и аксессуаров: каталог, варианты, остатки и экономика закупок с 1688.

## Запуск Windows

```powershell
dotnet build src/Dona.Crm.App/Dona.Crm.App.csproj -t:Run -f net10.0-windows10.0.19041.0
```

Нативные клиенты сохраняют рабочие данные локально в SQLite. Браузерный клиент использует browser storage. Google Drive (скрытая папка приложения) является явной целью синхронизации, а не обязательным сервером приложения.

## План развития и приоритеты

### P0 — импорт товара по ссылке из китайского магазина (временно отложен)

Этап временно отложен до появления стабильного доступа к китайским площадкам. После возобновления пользователь будет вставлять ссылку на карточку товара, приложение получит доступные данные, покажет предпросмотр и только после подтверждения создаст товар в каталоге.

Поддерживаемые источники первого этапа:

- 1688;
- Taobao и Tmall;
- Alibaba;
- Pinduoduo;
- другие китайские магазины через общий импортёр метаданных и отдельные адаптеры площадок.

План реализации:

1. Добавить отдельную страницу `Импорт по ссылке` в разделе каталога.
2. Определять площадку по домену, нормализовать ссылку и проверять, не импортирован ли товар раньше.
3. Получать доступные поля: название, описание, магазин/поставщика, цену в юанях, варианты, характеристики и изображения.
4. Хранить исходную ссылку и площадку в карточке товара.
5. Использовать готовую сущность `ProductImages`: ссылка, порядок, главное фото, подпись и источник хранения.
6. Показывать редактируемый предпросмотр до сохранения: пользователь проверяет перевод, категорию, SKU, варианты и фотографии.
7. Создавать поставщика или связывать товар с уже существующим поставщиком только после подтверждения.
8. Копировать выбранные фотографии в настроенное хранилище приложения — локально или в Google Drive, чтобы они не зависели от страницы магазина.
9. Добавить адаптеры площадок за единым интерфейсом, чтобы изменения одного магазина не ломали остальные импорты.
10. Добавить журнал импорта с результатом, ошибкой и исходной ссылкой.

Некоторые площадки требуют входа, используют динамическую загрузку или ограничивают автоматические запросы. Поэтому импортёр должен возвращать понятный результат, не создавать пустую карточку при ошибке и поддерживать безопасный запасной сценарий: заполненный предпросмотр с ручным добавлением недоступных полей. Поддержка «любого магазина» строится расширяемыми адаптерами, а не одним ненадёжным универсальным парсером.

Критерии готовности P0:

- ссылка вставляется в одном поле;
- площадка определяется автоматически;
- перед созданием товара всегда показывается предпросмотр;
- минимум название, исходная ссылка и фотографии переносятся в карточку;
- ссылки на фотографии можно выбрать, удалить и поменять местами;
- повторный импорт той же ссылки предупреждает о дубликате;
- ошибка загрузки не создаёт частично заполненный товар;
- импортированные данные одинаково сохраняются локально и в снимке Google Drive.

### Подключение Google

MAUI-версия не зависит от адреса Web и не использует отдельный DONA-брокер. В **Ещё → Подключения** достаточно нажать **Войти через Google**: ни таблицу, ни папку Drive указывать не нужно. Android авторизуется через Google Play Services, iOS — через системный OAuth с PKCE и callback приложения, Windows — через системный браузер с PKCE и loopback callback. Токены нативного приложения хранятся только в защищённом хранилище платформы. SQLite остаётся основным локальным хранилищем.

Данные синхронизации хранятся одним версионированным JSON-снимком `dona-crm-sync-v1.json` в скрытой папке приложения (`appDataFolder`) вашего Google Drive. Личные ZIP-копии и новые фотографии товаров тоже лежат в этой папке; она не видна в интерфейсе Drive и недоступна другим приложениям. Google Sheets не используется.

OAuth запрашивает только `openid email profile`, `https://www.googleapis.com/auth/drive.appdata` (снимок, резервные копии, новые фотографии) и `https://www.googleapis.com/auth/drive.file` (чтение и удаление фотографий, ранее созданных этим приложением вне скрытой папки). Полный scope `drive` и scope `spreadsheets` не запрашиваются. После смены scopes существующим пользователям нужно один раз выйти из Google и войти снова.

После подключения откройте **Сравнить данные**. Предварительный просмотр показывает количество записей по разделам и ничего не изменяет. Ручная загрузка Google Drive → устройство перед применением повторно проверяет fingerprint облачного снимка, после чего заменяет локальные данные одной операцией.

## Настройка Google Drive

1. В Google Cloud-проекте включите только Google Drive API (Google Sheets API больше не нужен) и настройте OAuth consent screen со scopes `drive.appdata` и `drive.file`.
2. Создайте отдельные OAuth-клиенты для используемых платформ:
   - **Web application** — для `Dona.Crm.Web.Client`; Client ID встроен в браузерную версию по умолчанию;
   - **Android** — для package name `com.tnadevelopment.donacrm` и SHA-1 сертификата подписи; Client ID в приложении вводить не требуется;
   - **iOS** — OAuth-клиент для bundle ID `com.tnadevelopment.donacrm` встроен в приложение; callback: `com.googleusercontent.apps.440684132138-iudhahju73tqgkkjr4i7oetgnu8ra7mn:/oauthredirect`;
   - **Desktop app** — для Windows; Client ID и Client Secret читаются из `appsettings.{Environment}.json` (ключи `GoogleOAuth:WindowsClientId` и `GoogleOAuth:WindowsClientSecret`) и поставляются вместе с приложением. Google не считает секрет установленного приложения конфиденциальным, поэтому пользователь его не вводит.
3. Добавьте используемый Google-аккаунт в список тестовых пользователей OAuth, пока приложение находится в режиме Testing.
4. В **Ещё → Подключения** нажмите **Войти через Google**, затем при необходимости включите хранение новых изображений в Drive.
5. Используйте **Сравнить данные** перед первой синхронизацией.

Один Google-аккаунт используется для всех операций, приложение не хранит service-account JSON и не требует постоянно работающего сервера. Scopes `drive.appdata` и `drive.file` не относятся к restricted, поэтому платная проверка безопасности (CASA) для публичного релиза не нужна; в режиме Testing аккаунт пользователя должен быть добавлен как test user.
