# Dona CRM

Command Orbit использует единый интерфейс из `Dona.Crm.UI`: `Dona.Crm.App` запускает его как MAUI Blazor Hybrid на Android, iOS и Windows, а `Dona.Crm.Web.Client` — как браузерное WebAssembly/PWA-приложение. Старый серверный Web-host удалён после переноса бизнес-логики, синхронизации, Google Drive и регрессионных тестов.

## Command Orbit в браузере

```powershell
dotnet run --project src/Dona.Crm.Web.Client
```

Браузерная версия работает без серверного брокера: локальный снимок хранится в browser storage, интерфейс доступен как PWA, а Google OAuth использует Web Client ID напрямую. Ручная синхронизация пишет версионированный снимок в скрытый лист `_CommandOrbitSync` выбранной Google-таблицы и проверяет версию перед заменой данных.

Локальная мини-CRM для магазина одежды и аксессуаров: каталог, варианты, остатки и экономика закупок с 1688.

## Запуск Windows

```powershell
dotnet build src/Dona.Crm.App/Dona.Crm.App.csproj -t:Run -f net10.0-windows10.0.19041.0
```

Нативные клиенты сохраняют рабочие данные локально в SQLite. Браузерный клиент использует browser storage. Google Sheets является явной целью синхронизации, а не обязательным сервером приложения.

## План развития и приоритеты

### P0 — импорт товара по ссылке из китайского магазина (временно отложен)

Этап временно отложен до появления стабильного доступа к китайским площадкам. После возобновления пользователь будет вставлять ссылку на карточку товара, приложение получит доступные данные, покажет предпросмотр и только после подтверждения создаст товар в каталоге.

Поддерживаемые источники первого этапа:

- 1688;
- Taobao и Tmall;
- Alibaba;
- Pinduoduo;
- другие китайские магазины через общий импортёр метаданных и отдельные адаптеры площадок.

План реализации:

1. Добавить отдельную страницу `Импорт по ссылке` в разделе каталога.
2. Определять площадку по домену, нормализовать ссылку и проверять, не импортирован ли товар раньше.
3. Получать доступные поля: название, описание, магазин/поставщика, цену в юанях, варианты, характеристики и изображения.
4. Хранить исходную ссылку и площадку в карточке товара.
5. Использовать готовую сущность `ProductImages`: ссылка, порядок, главное фото, подпись и источник хранения.
6. Показывать редактируемый предпросмотр до сохранения: пользователь проверяет перевод, категорию, SKU, варианты и фотографии.
7. Создавать поставщика или связывать товар с уже существующим поставщиком только после подтверждения.
8. Копировать выбранные фотографии в настроенное хранилище приложения — локально или в Google Drive, чтобы они не зависели от страницы магазина.
9. Добавить адаптеры площадок за единым интерфейсом, чтобы изменения одного магазина не ломали остальные импорты.
10. Добавить журнал импорта с результатом, ошибкой и исходной ссылкой.

Некоторые площадки требуют входа, используют динамическую загрузку или ограничивают автоматические запросы. Поэтому импортёр должен возвращать понятный результат, не создавать пустую карточку при ошибке и поддерживать безопасный запасной сценарий: заполненный предпросмотр с ручным добавлением недоступных полей. Поддержка «любого магазина» строится расширяемыми адаптерами, а не одним ненадёжным универсальным парсером.

Критерии готовности P0:

- ссылка вставляется в одном поле;
- площадка определяется автоматически;
- перед созданием товара всегда показывается предпросмотр;
- минимум название, исходная ссылка и фотографии переносятся в карточку;
- ссылки на фотографии можно выбрать, удалить и поменять местами;
- повторный импорт той же ссылки предупреждает о дубликате;
- ошибка загрузки не создаёт частично заполненный товар;
- импортированные данные одинаково сохраняются в локальном JSON и Google Sheets.

### Подключение мобильного приложения

MAUI-версия не зависит от адреса Web и не использует отдельный DONA-брокер. В **Ещё → Подключения** пользователь выбирает существующую Google-таблицу и, при необходимости, папку Drive. Android авторизуется через Google Play Services, iOS — через системный OAuth с PKCE и callback приложения, Windows — через системный браузер с PKCE и loopback callback. Токены нативного приложения хранятся только в защищённом хранилище платформы. SQLite остаётся основным локальным хранилищем.

OAuth запрашивает разрешение Google Sheets для чтения и записи существующей таблицы по её ID и ограниченный scope `drive.file` для файлов, которые пользователь открывает или создаёт через DONA CRM. Полный доступ ко всему Google Drive не запрашивается.

После подключения откройте **Сравнить SQLite и Google Sheets**. Предварительный просмотр показывает количество записей по разделам и ничего не изменяет. Первая поддерживаемая операция — ручная загрузка Google Sheets → SQLite: перед применением приложение повторно проверяет fingerprint облачного снимка, после чего заменяет локальные коллекции одной SQLite-транзакцией. Google-таблица этой операцией не изменяется.

## Настройка Google Sheets и Google Drive

1. В одном Google Cloud-проекте включите Google Sheets API и Google Drive API, настройте OAuth consent screen.
2. Создайте отдельные OAuth-клиенты для используемых платформ:
   - **Web application** — для `Dona.Crm.Web.Client`; его Client ID вводится на странице подключений;
   - **Android** — для package name `com.companyname.dona.crm.app` и SHA-1 сертификата подписи; Client ID в приложении вводить не требуется;
   - **iOS** — для bundle ID `com.companyname.dona.crm.app`; Client ID вводится на странице подключений;
   - **Desktop app** — для Windows; Client ID вводится на странице подключений.
3. Добавьте используемый Google-аккаунт в список тестовых пользователей OAuth, пока приложение находится в режиме Testing.
4. В **Ещё → Подключения** вставьте ссылку или ID существующей Google-таблицы, укажите платформенный Client ID там, где поле показано, и войдите в Google.
5. При необходимости укажите ID папки Drive, доступной этому OAuth-клиенту, и включите хранение новых изображений в Drive.
6. Нажмите **Проверить**, затем используйте предварительное сравнение SQLite и Google Sheets перед первой синхронизацией.

Один Google-аккаунт используется для Sheets и Drive. Приложение запрашивает доступ к выбранной таблице и scope `drive.file`, не хранит service-account JSON или OAuth client secret и не требует постоянно работающего сервера. Фотографии Drive загружаются и читаются напрямую через Google API; локальные фотографии остаются доступным вариантом.
